# observability-core-vector

Standalone, offline figure/report package that answers one question about the
LUMO lattice tower (Hannover): does the **observability core vector**

```
OCV = [gamma2, P, D] = [interferometric coherence, mask persistence, mask density]
```

discriminate the four LUMO structural states (healthy, DAM3, DAM4, DAM6) — or
are the states indistinguishable with respect to these three quantities?

The package contains no new measurement. It **recomputes** the committed LUMO
numbers from one overpass table, renders five figures (A–E) plus an English
report, and **pins every number against five committed reference JSONs**: a
single deviation makes the run exit with a non-zero status. The claim of the
repository is therefore not "we assert", but "we reproduce and read off".

Start here for the results:
[`figures/fig_lumo_ocv_paper.md`](figures/fig_lumo_ocv_paper.md) (report,
regenerated by the scripts) and [`figures/`](figures/README.md) for the five
figures.

## What the figures show

| figure | question | content |
| --- | --- | --- |
| A | what do the channels look like? | raw distributions of gamma2, A, D, F, S, P over the 178 coherence overpasses, per state |
| B | which component carries a difference? | in-sample effect sizes: Cliff's delta, bootstrap CI, SDS = 10&#124;delta&#124;, for all six components |
| C | is the state recoverable at all? | 4-class LDA, leave-one-out, shrinkage grid, confusion matrix, label-permutation null |
| D | is the separation state-specific? | out-of-fold scores of the six binary state pairs for four feature sets (+ paired bootstrap vs. gamma2 alone) |
| E | is it the state driving it? | severity trend (Jonckheere-Terpstra, Spearman), season/orbit strata, mask brightness and wind covariates |

`P` belongs to the core vector; `A`, `F` and `S` are controls for the
*morphology* of the same echo mask (they are all derived from the identical mask
as `P` and `D`).

## Folder structure

```
observability-core-vector/
├── code/     analysis + plotting scripts: read data/*.csv | data/*.json and
│             write data/*.json or data/*.csv — see code/README.md
├── data/     the copied LUMO overpass table, the extended table generated from
│             it, and copies of the five committed LUMO reference JSONs that the
│             pin block verifies against — see data/README.md
├── figures/  the .sh wrapper that runs the figure script, plus the .md report
│             and the .png figures it writes — see figures/README.md
├── .gitignore
└── README.md
```

## Quick start

```bash
cd research/observability-core-vector

# 1) figures + report + JSON, verified against the committed references
bash figures/fig_lumo_ocv_paper.sh            # ~5 min (two permutation tests)
bash figures/fig_lumo_ocv_paper.sh --quick    # ~2 min (permutation tests copied)
# if the python3 of PATH has no numpy/matplotlib: PYTHON=/usr/bin/python3 bash figures/...

# 2) only if data/lumo_ocv_channels.csv has to be rebuilt from the burst cache
python3 code/lumo_ocv_channels_csv.py
```

Everything is offline and deterministic: fixed seeds (RNG seed 11, 2000
bootstrap draws, 1000 / 500 permutation draws), no timestamps in any output, so
repeated runs produce identical JSON, Markdown and PNG files. Requirements:
Python 3 with numpy, matplotlib and scipy (scipy only for the p-values of the
control tests).
